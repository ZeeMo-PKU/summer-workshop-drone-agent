# 吊舱可见光实时流恢复

本文记录 2026-08-05 已验证的 `PodVisibleLight` / `ov48` 恢复流程。该流程只允许在飞机落地后执行。

## 安全前置条件

必须同时确认：

- `flight_path=STANDBY`
- `armed=false`
- 高度为 0
- 没有比赛或其他控制进程

飞机在空中时禁止重启媒体工作进程或吊舱设备。

## 分层恢复

1. 使用 `ffprobe` 检查 `rtsp://192.168.1.120:8554/arRtspStream`，确认是连接失败而不是上层取帧代码错误。
2. 先终止 Jetson 侧当前 `ov48` 媒体工作进程，让 `iking_drone_app_node` 守护逻辑自动拉起新进程；记录旧、新 PID，并重新探测 RTSP。
3. 如果 RTSP 仍未恢复，使用吊舱官方 OTA 页面提供的接口：`POST http://192.168.1.120:8080/restart`。
4. 等待吊舱网络端口恢复，再次用 `ffprobe` 验证编码、分辨率和帧率。
5. 最后运行官方 SDK 示例 `06_pod_frame_acquire`，要求实际保存新帧且没有 `FrameTimeout(1010)`。
6. 操作完成后再次确认飞机为地面待机状态，且没有遗留控制进程。

## 本次验证结果

- 单独重启 Jetson 侧 `ov48` 工作进程无效。
- 吊舱官方 `POST /restart` 恢复了 RTSP。
- 恢复后流格式为 H.264、1280x720、25 fps。
- SDK 连续取帧 3/3 成功，0 次超时。
- `gimbalDownSet` 返回成功但画面朝向天花板，方向校准仍需单独处理。

完整证据见 `test-data/runs/20260805-131600/`。
