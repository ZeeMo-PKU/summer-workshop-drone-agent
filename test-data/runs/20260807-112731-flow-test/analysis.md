# 便携场地仿真测试：闭环通过但投球位置错误

- 运行编号：`20260807-112731`
- 环境：`CFG_FLIGHTSIM=1`
- 任务高度：`7.0 m`
- 安全范围：水平半径 `20 m`，相对高度上限 `10 m`
- 结论：飞行、触发、双路拍照和返航链路完成；投球落入相邻物理位，整轮不能判定为通过。

## 已验证流程

1. 接收 `MATCH_STARTED` 后闭合夹爪并起飞至 7 米。
2. 到达 B 场景区，裁判于 `03:29:16Z` 报告进入触发区，程序确认连续稳定悬停 3000 毫秒。
3. 收到题目 `REAL-3-01`，仿真答案为 B；前向相机成功保存 `scene_B.jpg`。
4. 飞到程序定义的物理位 2，下摄吊舱成功保存 `answer_layout.jpg`，布局为 `A=3, B=2, C=1`。
5. 夹爪只打开一次；裁判随后返回 `ANSWER_WRONG`。
6. 程序返回启动点并降落。最终只读状态为 `STANDBY`、`armed=false`、高度 0、无控制进程。

本轮设置了 `IKING_ALLOW_SIM_ORACLE=1`，语义答案和布局直接使用裁判仿真标记，未调用外部 Qwen/OpenRouter。因此本轮验证的是飞行控制闭环，不是视觉识别准确率。

## 投球错误根因

SDK 的绝对位置接口为 `setPosition(float longitude, float latitude, ...)`，经纬度参数只有单精度。在当前经度约 119.713 度的位置，相邻 `float` 经度约相差 `0.659 m`，而三个答题位的中心间距只有 `0.52 m`。

投球时遥测经度被量化为 `119.71370697021484`。按监控系统的 `-90` 度场地旋转换算，释放位置约为 `x=0, z=-3.29655`：

- 距物理位 A 中心 `0.19345 m`，位于 A 的 `0.31 m` 半径内；
- 距物理位 B 中心 `0.32655 m`，刚好在 B 的 `0.31 m` 半径外。

因此程序虽然发送了物理位 2 的目标，裁判却检测为物理位 A，最终判错。程序自身显示距离为 0，是因为它也在与同一个已量化目标比较，无法发现这个偏差。

## 返航行为

返航遥测最高达到 `9.974 m`。这没有超过 10 米安全上限，但高于 7 米任务高度，说明当前 `returnToAnyPosition` 会触发飞控的返航高度策略，也会增加返航时间。

## 公开数据处理

前向原图中有多名可识别人员和手机画面，因此完整原始运行目录只保存在本机私有归档，不推送到公开仓库。公开副本保留全部日志、遥测、服务器原始哈希清单和不含人员的下摄照片。`SERVER_SHA256SUMS` 可用于核对私有原始目录，`PUBLIC_SHA256SUMS` 用于核对当前公开副本。

下一次飞行前必须先解决窄间距答题位的定位精度问题，并验证不会因绝对经纬度单精度再次落入相邻区域。
